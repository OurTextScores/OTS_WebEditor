## Page navigation (`components/score-editor/page-turns/`)

`PageNavigator` replaces `goToPageImpl` (deleted along with its tests; their contract moved to the navigator
tests):

- **Latest target wins.** Requests coalesce; superseded ones resolve `false`. Navigation is no longer dropped while
  another one is in flight.
- **Intents.** `manual` (user paging, Go to page, chord navigation), `playback` (following) and `reveal`
  (Jump/Resume). A manual request supersedes a pending automatic turn, and automatic turns are refused while a
  manual one is pending.
- **Atomic commits.** The SVG is fetched first. The SVG, `currentPageRef` and page state are then committed
  together, only if the request is still the latest and no other canvas render started meanwhile (otherwise it
  retries once). The old code set the page before rendering, leaving a window of mismatched page and SVG.
- **One install generation** (`pageInstallGenerationRef`) is shared with `renderScore`. Every render claims a
  generation and only installs if it is still the newest, so an old render can no longer overwrite a newer page or
  score. A superseded render returns success, not failure.
- **Bounded cache** (`PageSvgCache`): at most 3 pages and 6 M characters, LRU, scoped to one score object. It is
  cleared by any other render of the canvas (edits, selection repaints, font/layout changes), because the
  navigator cannot prove a cached page still matches the score.
- **Failures and progressive layout.** A failed or missed page leaves the current page readable. Progressive pages
  are laid out on demand, with one layout retry after a failed render. While following waits on an unprepared
  page, the header shows "Preparing page N…".

## Prepared turns

Following finds the next page change in performance order with `nextPageChange`, so a repeat or jump back to an
earlier page is prepared like a forward turn. It prefetches that page once it is within a rolling lead: at least
6 s, or 4× the measured average page render.

Prefetch also requires an audio cushion. The transport now publishes its scheduled-PCM frontier
(`PlaybackSessionOwner.frontierRef`, `bufferedAheadSeconds()`), and a prefetch waits until at least
max(1.5 s, 3 average renders) of audio is already scheduled. Page work runs on the shared engine queue between
audio pulls. The first design gated on `renderWindowIdle` (a full 20 s horizon), which never arrived in the
seconds after a seek, so the next page was never prepared.

System following inside a page is unchanged from Phase 4 (safe region, horizontal reveal, reduced motion). The
player now uses the same policy (`usePlayerFollowScroll`): it scrolls only when the active system leaves the
readable band. Previously it smooth-scrolled to 28% of the viewport on every highlight change, which in note mode
meant every note.
