## Shared transport

The editor now uses `useScoreTransport`, the same controller hook as the embedded player. The new
`components/score-editor/playback-session/` adapter supplies editor selection synthesis, startup options,
click preferences and shell state. The former editor main-stream/media-element orchestration was removed;
selection audition remains separate. WAV compatibility now decodes once into a cached Web Audio buffer and
uses the same context, gain, pause/resume and presentation clock as streamed playback.

`PlaybackSessionOwner` is the shared controller core for editor/player and the compare-side adapters. It
owns attempt IDs independently of scheduler generations, source/iterator refs, presentation anchor/position,
phase and outstanding preparation/cancellation work. Separating these generations fixes a compare bug:
the scheduler increments its stream generation, which previously made successful preparation look stale
and could leave the side busy. Compare retains its existing operation coordinator and per-pane UI state.

`useScoreTransport.start(request, targetMs)` supports default full/absolute-time synthesis and custom
selection/range iterator factories. Factory callbacks receive the score, absolute start seconds and an
`isCurrent` predicate for multi-step preparation. Selection keeps its existing 120 ms preroll, 600 ms startup
buffer, three startup batches and 500 ms merging. Full playback keeps its existing settings. The 20/10-second
render horizon is unchanged.

Compact `state` preserves the current UI adapter contract. Detailed `phase`/`phaseRef` additionally exposes
`count-in`, `buffering`, `draining` and `cancelling`. The owner exposes bounded resource diagnostics and an
underflow counter. No tempo/repeat UI, seeking gestures or score-following overlay is introduced here.

## Cancellation and editing

- Play creates/resumes AudioContext from the gesture before font/worker awaits. Compare does likewise.
- Attempts exist before an iterator does. Stop immediately invalidates the attempt, clears the anchor and
  stops browser sources/clicks. Its returned promise also drains work that could touch the score, including
  a late iterator's cancellation. A newer attempt cannot be overwritten by an older completion.
- Stop is enabled in the editor during preparation. Preparation can complete after Stop, but cannot start
  audio. Native preparation is not interruptible midway through a worker call.
- The editor mutation pipeline awaits retirement. Loaded editor scores also receive a narrow proxy over an
  explicit list of notation/lifecycle APIs, covering direct commands, undo/redo, drag/drop, part changes and
  destruction. Ordinary selection, note-input state, background layout and CSS zoom continue playing.
  Explicit user relayout still goes through the mutation pipeline and stops playback.
- Retiring a stale loaded score does not stop a newer displayed score. Score replacement awaits destruction
  after cancellation. Fallback buffers are invalidated before notation edits and font replacement.
- Compare mutations and merged-score edits await cancellation. SoundFont upload and WAV exports stop the
  current browser output before changing/using the native mixer. Existing compare teardown coordination is retained.
- Context disposal detaches captured resources before awaiting retirement, so delayed cleanup cannot close a
  context created by a newer attempt or a StrictMode remount.

The retirement promise may wait for an outstanding font installation or native call. UI Stop takes effect
immediately; callers that will mutate/destroy the score must await retirement rather than treating Stop's
immediate UI update as completion.

## Presentation and buffering

`clockRef` contains a context-time/absolute-score-time anchor. `positionRef` and `subscribePosition` provide
frame updates without worker calls. The editor opts out of React position updates; subscribers can animate a
future overlay without re-rendering the editor composition root. The player retains its existing time-label
updates. Count-in holds position at the music start; pause freezes the context clock; draining retains the
clock through the tail. WAV mode uses the same anchor and count-in path.

The scheduler watches the actual scheduled PCM frontier while awaiting a worker pull. Suspended contexts do
not advance that watchdog. Starvation freezes presentation at the last scheduled score position and stops
clicks. Recovery removes exhausted old sources, schedules subsequent PCM on a fresh future anchor, publishes
that same anchor to presentation, and restarts clicks from the recovered position. It never schedules a late
block in the past, where Web Audio would start several blocks immediately.

Implementation refinement from the design: recovery retains the sequential native iterator and its rendered
PCM, rather than discarding it and requesting the same music again. The native stream remains valid; browser
sources and the scheduling epoch are replaced. This preserves the next unplayed sample and avoids additional
native preparation under a worker stall. Recovery uses the existing preroll and available batch, with no new
startup-buffer tuning or fade policy. Repeated stalls remain observable; performance tuning belongs to Phase 8.

The presentation clock remains AudioContext-based. Device output-latency alignment, cross-browser/device
qualification, page rendering/snapshot generations and visible following controls remain later phases.
