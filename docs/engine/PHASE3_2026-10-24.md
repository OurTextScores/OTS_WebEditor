## Native options contract

`engine/musescore/bridge/playbackoptions.h` holds transient per-project options: `tempoMultiplier` (clamped to
0.25–2.0; non-finite input keeps the previous value) and `playRepeats` (default on). Excerpts share the project's
options because they share the master score's tempo map and repeat lists. `setPlaybackOptions` returns the accepted
options and a `revision` that changes only when an option does. A change retires the project's prepared stream and
playback model, because their PCM and timing belong to the previous revision.

Every playback-family read runs inside one `PlaybackOptionsScope`: synthesis (full, selection, range, preview,
WAV), `playbackTimeline`, `savePositions`, `selectionPlaybackStartTime`, measure-range windows and both position
conversions. The scope multiplies the score's own tempo multiplier (1.x files may carry one), sets repeat expansion,
rebuilds the repeat list *without* upstream's tie-repair pass (which pushes undoable edits), and restores all of it
on exit. The hardcoded `setExpandRepeats(true)` / `setPlayRepeats(true)` overrides are gone. MIDI, MusicXML and MSCZ
exports, layout and undo never observe the options. Timeline and positions report `optionsRevision`; capabilities
advertise `playbackOptions` (schema 1, range, `positionConversion`).

Positions use written tick plus repeat pass. `playbackPositionAt(ms)` returns `writtenTick`, `fractionalTick`
(progress through the tick), `occurrenceIndex`, `pass` (0 on the first pass over that tick) and `atEnd`.
`playbackTimeForPosition` returns the time under the current options, plus an explicit fallback:
`pass-unavailable` (nearest remaining pass, e.g. repeats turned off), `tick-unreachable` (next reachable written
location) or `end`. A location never silently restarts from zero.

Semantics, matching desktop MuseScore 4.7 by decision:

- Repeats off is upstream's non-expanded traversal: every written measure once, both endings included, jumps
  (D.C./D.S./coda) ignored.
- The multiplier scales the tempo map, so tempo changes inside a measure and fermata holds scale. Timed pauses
  (breath/caesura, section-break pause) are added unscaled, as on desktop. The verifier fixture has no timed pause,
  so that case is upstream behaviour, not something verified here.
- Pitch is unchanged; tempo is never faked with buffer playback rate.

## Transport

`useScoreTransport().setPlaybackOptions(request)` (in `lib/playback/options-transaction.ts`) is position-preserving:

- Captures the presentation time and its musical location under the old options, then retires old-option audio and
  clicks before the native change. Applies every pending request (latest wins) in one transaction, then maps the
  original location under the settled options. An intermediate repeats-off state cannot erase the original pass.
- Playing/preparing: restarts at the mapped time with no count-in. A later explicit Play can count in. Requests
  marked `restartable` keep their factory (the editor's full play now honours its start time); selection play
  restarts as a full stream from the mapped time.
- Paused: stays paused at the mapped location and renders nothing until resume. Idle/ended: only the playhead moves.
- Stop or Play during the transaction supersede the resume. Play waits for the options to settle and moves an
  old-time-base target with them.
- Clears compatibility WAV (regenerated under the new options on next use) and overrides the duration until the host
  passes the new timeline's. On older engines it returns `unavailable` and leaves playback untouched.

The player re-reads its timeline, measure positions and (in note mode) note positions when the accepted revision
changes (`usePlaybackOptionsRefresh`), so following, clicks and seeking use the audio's traversal.

## Phase 2 regression fixed here

Phase 2 put `setLayoutMode` and `setMeasureLineBreaks` behind the notation boundary. Compare reflow writes both to
the score a compare pane is playing (the current score is the right pane), so starting right-pane playback stopped
it immediately. `tests/compare-close-during-playback.spec.ts` failed at `eeab4dd1` and passed at `19889edf`; Phase
2's verification had not run it. Both methods are now unguarded: neither changes what sounds, and user line/page-
break toggles stay guarded. A unit case in `unit/playback-session.test.tsx` pins this (mutation-checked).
