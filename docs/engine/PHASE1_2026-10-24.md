# Playback / score-following Phase 1 execution record

Date: 2026-10-24 (America/Vancouver).

Status: **Phase 1 complete and committed.** Phase 0 was committed separately as `09164bbd`.

## Implemented

- Replaced raw stream-state addresses with monotonic opaque IDs and one optional active stream. Superseding a
  stream, replacing a font or destroying its score invalidates ownership. Stale pulls/cancels return empty done
  records without rendering or stopping another owner. Cancellation and natural completion reclaim stream state.
- Restricted the shared mixer to the current score's sequence. Preparing another score removes prior sequences
  and playback models; old tracks cannot sound beneath a new score. Full WAV rendering also supersedes streaming.
- Made measure/segment position export safe when systems/pages are missing. Missing boxes retain IDs/timing with
  `geometryAvailable: false`, page `-1` and zero finite geometry. Added `complete`, schema version and written-tick
  anchors. Clipped events to their repeat segment. The player ignores placeholders for following/highlighting.
- Added native generation invalidation before JS replaces the shared soundfont file. A narrow upstream patch
  releases FluidSynth's decoded filename cache after synth voices are released. Failed eviction prevents overwrite;
  invalid replacement data cannot reuse old cached audio. The builder applies the ordered tracked patch list.
- Added `score.playbackCapabilities()` across native, JS, worker and app types. Old/mixed engines return `null`.
  Added bounded native lifecycle diagnostics for verification. The legacy PCM binary layout remains unchanged.
- Added explicit PCM source metadata and validation. Web Audio buffers use the 44.1 kHz source rate even on a
  48 kHz context, including merged buffers. Empty terminal records do not create silent sources.
- Rebuilt, bundled, installed and synchronized the engine and regenerated the static embed.

The implementation preserves full/selection/range/preview APIs and the existing transport UI, buffer sizes and
render horizon. It does not implement Phase 2 transport ownership, tempo/repeat controls or score following UI.

## Findings verified during implementation

**The old decoded-font cache survives synth destruction.** Generation bookkeeping alone initially left replacement
audio unchanged. The regression fixture generates two original sine-preset SF2 files with the same bank/preset name
and installation path, using different attenuation. With the cache-eviction patch, measured peak changes from
`0.07960957288742065` to `0.00010494585876585916`; without eviction it stayed identical. No external sample assets
are needed for this test.

**`doLayout=false` currently does not prevent initial layout.** Upstream `setupMasterScore()` calls `update()` after
requesting layout, before the bridge's explicit layout step. Fixing deferred-load performance remains separate.
The incomplete-layout regression therefore uses a Node-only harness probe that temporarily detaches selected layout
parents and invokes the real writer. IDs, timing and finite placeholders are checked, followed by exact restoration.
The production browser package and application Node bundle exclude the fault-injection export; tests assert that.

Array IDs remain scoped to a layout snapshot. `writtenTick` supplies a musical anchor across layout changes;
notation edits and multi-measure-rest regrouping still require snapshot invalidation/mapping in subsequent phases.
Native invalidation cannot remove PCM already scheduled in Web Audio; browser-source cancellation belongs to the
transport work in Phase 2.
