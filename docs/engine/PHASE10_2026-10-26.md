## Scope and repeatable runs

The [68-spec inventory](PHASE10_EDITOR_SPECS.txt) covers the editor beyond Phase 9 playback: keyboard routing,
note input, pointer selection and drag, SVG hit testing, grips, menus, palettes, panels, inspector, file loading,
compare, undo, notation controls and embedded mode. The existing Phase 9 playback matrix is complementary. All 35 existing host smoke specs run in all three browsers: even API-heavy specs retain this coverage because the measured total cost is about four minutes per browser. Credential/provider-dependent cases keep their existing opt-in skips.
Engine semantics are also exercised in this set because they share browser-worker calls; native-only verifiers
remain outside the browser matrix. Tests requiring external music providers or the dedicated static embed host
keep their own configurations. This phase does not claim untested IME/device behavior is qualified.

Run one browser at a time locally; concurrent WASM jobs caused false timeouts. The runner persists each spec's
result and artifacts under `.playwright-runs/<name>/`, which is intentionally ignored by git.

```bash
PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu24.04-x64 PLAYWRIGHT_PORT=3013 \
PLAYWRIGHT_BROWSER=firefox node scripts/playwright-resumable.mjs \
  --run phase10-firefox-pw --specs-file docs/engine/PHASE10_EDITOR_SPECS.txt --rerun-failed
```

Use `chromium` or `webkit` for the other legs. See [Phase 9](PHASE9_2026-10-25.md) for Linux WebKit audio/library
setup and why Playwright Firefox timings do not represent users' Firefox. The browser selector remains an
environment variable in OTS_Web; OurTextScores uses named Playwright projects. CI explicitly chooses each browser.

## Product fixes

- `c5b77b38`: start score mutations in invocation order. Rapid note entry with a soundfont installed previously
  produced E D F from D E F. This was a real editor bug, including Chromium, rather than Firefox/WebKit timing.
- Grip edits: the click generated after pointer release could call `endGripEdit(false)` while the asynchronous
  drag commit was still running. The native edit is now owned by the finishing gesture before it awaits worker
  replies; ordinary click cleanup cannot cancel that commit. Starting another edit ends the previous open edit.
  A successful commit explicitly refreshes undo history so the toolbar reflects the native undo stack.
  The slur reshape-and-undo regression passes in focused Firefox and WebKit runs.
- Phase 9's root-SVG coordinate mapping, portaled popovers and compressed MusicXML import remain in the shipping
  source. See its report for evidence. The fixture commit `1cdee306` also restores a score needed by eight specs.

## CI unit-test follow-up

The [CI unit run](https://github.com/OurTextScores/OTS_WebEditor/actions/runs/40406827698/job/121866637824)
reported two failures missed by the browser-focused qualification:

- The grip-hook unit fixture provided a partial `EditorCore` without `undoHistory.refresh`. The new successful
  grip commit reached that missing dependency and exited through its error handler before relayout. The fixture
  now supplies the history refresh and asserts it is called. A deferred-worker regression also verifies that
  closing edit mode after pointer release cannot cancel the pending commit or add an extra native end call.
- The selection test retained the original SVG path across the selection-triggered redraw. Its second click
  could hit a detached node, never reach the editor and leave the old overlay visible. The test now waits for
  that redraw and targets the live replacement path. It retains the assertion that invalid geometry clears
  the overlay and verifies that no additional native selection was requested.

These are test-fixture corrections; production code and the vendored bundle are unchanged. Focused verification:
