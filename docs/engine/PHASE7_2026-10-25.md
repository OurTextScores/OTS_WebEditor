## Native follow map (`engine/musescore/bridge/followmap.h`)

`playbackFollowMap()` returns repeat-expanded cursor intervals under the project's playback options (Phase 3
scope), with page-local 360-dpi geometry. Capabilities advertise `followMapSchemaVersion: 1`.

Geometry follows desktop `PlaybackCursor::resolveCursorRectByTick`:

- **Horizontal:** within a measure x moves linearly *in ticks* from one visible ChordRest segment to the next, the
  last one ending at the end barline.
- **Vertical:** the band runs from the first to the last visible staff, ±3 spatium. Hidden staves are excluded.
- **Multi-measure rests** use the rest the page shows, moving across its full width over the combined duration.

Time is linear in ticks only between tempo-map entries, so each interval is split at every entry inside it. That
makes the interpolation exact for in-measure tempo changes, fermatas and gradual tempo changes (an accelerando or
rallentando is stepped tempo-map entries; `Score::rebuildTempoAndTimeSigMaps` uses at least 8 steps). A timed pause
before a tick (caesura, breath pause) becomes a hold interval at that tick's x.

- **Shared ids:** segment ids match `segmentPositions()`, measure and occurrence indices match `playbackTimeline()`,
  and system ids are global per score.
- **Missing layout:** an unlaid measure keeps its timing with `geometry: null`. Verified with the Node-only probe,
  which detaches layout parents.
- **Cost:** bach (3 pages, 657 intervals) 12–17 ms native, ~139 KB JSON.

## Browser

`lib/playback/score-following/follow-map.ts`:

- **Validation:** `buildFollowMapIndex` validates the map at the boundary (schema, finite and positive intervals,
  ordered starts, integer pages). Anything off contract returns null.
- **Resolution:** `resolveContinuousCursor` binary-searches the half-open `[startMs, endMs)` interval and
  interpolates only within it.
- **Edges:** before the first interval there is no cursor, and after the last it holds at the final barline.
  Repeats, jumps and system or page changes are jumps, never sweeps.
- **Placement:** desktop's, one spatium before the position and 0.4 spatium wide.

- **Editor:** `PlaybackFollowLayer` draws a bar whose transform is written directly from the transport's position
  ticks: no React render and no engine call per frame (verified in the browser by counting engine calls during
  playback). The discrete segment cursor still drives page and system following, and remains the drawn fallback.
  The map is used only if its options revision and duration agree with the segment map and timeline read with it
  (a lesson from segno-player: a wrong cursor is worse than a discrete one).
- **One cursor element:** with a map, the moving bar *is* `playback-cursor` (`data-kind="continuous"`). It keeps the
  discrete segment's `data-element-id`/`data-start-ms`, so tests and tools see one cursor in either mode.
- **Manual scrolling (from the Viritura player review, design §20):** a wheel, touch drag, scroll key or scrollbar
  press now suspends following only if, once the scroll settles (150 ms), the playback position is no longer in
  view. Scrolling that keeps it visible leaves following on; a manual page change still suspends.
- **Player:** draws the same cursor from the same resolver and keeps its own measure shading and note colouring;
  the measure's leading line gives way to the moving cursor. Seeking in both editor and player now uses one rule
  (`passTime`): the pass inside the repeat run now playing, else the next pass, else the first. The player
  previously took the next pass after now. The player refreshes the map with timeline and positions on an options
  revision.
- **Video export:** a new **Cursor** option (None by default, Moving cursor) resolves each frame with the same
  resolver at the frame's music time. Frame de-duplication now includes the cursor, so frames that differ only by
  it are not dropped.

### Repeat corpus (from the segno-player review)

`tools/musescore/verify-repeat-corpus.mjs` (`MS47_VERIFY_REPEAT_CORPUS=1`) loads all 69 scores of MuseScore's own
repeat test suite from the pinned checkout. It checks that our timeline and follow-map orders equal the played
measure numbers in `repeat_tests.cpp`: **69/69 match**. The wider review is recorded in the design doc, §19.
