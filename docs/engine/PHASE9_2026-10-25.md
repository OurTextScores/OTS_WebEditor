### Test-only fixes

- `playback-options-wasm`: installs the soundfont itself (it raced the app's background warm-up).
- `video-export`: encoding tests skip when no codec can be encoded, checked on the app's page as the app does
  (WebCodecs is secure-context only, so `about:blank` misreports); a new test checks the "cannot encode" path; the
  H.264 regression test skips without an H.264 encoder.
- `playback-following` (Play from selection): measures note positions only after the fit-zoom transition settles;
  WebKit was still animating it.
- `playback-follow-map` (player smoothness): skips when the browser delivers fewer than 8 animation frames in the
  200 ms window; software-rendered WebKit gives frames hundreds of ms apart during playback, where smooth and
  discrete cursors cannot be told apart.
- `embedded-score-player`: asserts the transparent marker fill.

### Environment findings (not product bugs)

- **Playwright's Firefox has no optimizing WebAssembly compiler.** Forcing `javascript.options.wasm_baselinejit=false`
  aborts with "no WebAssembly compiler available". A standalone `-O3` wasm benchmark in a worker: Chromium 249 ms,
  **stock Firefox 158 312–486 ms**, Playwright Firefox 1,238–1,370 ms (automated or not). On the engine it was ~10×
  slower than Chromium (page render 1.2–2.6 s vs 133–201 ms). Valid for correctness; timing needs stock Firefox or a
  device. (Its automation also attaches a JS `Debugger` to page and worker globals; the non-automated run showed this
  was not the cause.)
- **WebKit (WPE):** `getOutputTimestamp().performanceTime` is ahead of `performance.now()` by `contextTime`;
  Phase 8's validation already rejects future stamps and falls back to `currentTime` (8.7 ms granularity). No
  usable WebCodecs codec. Animation frames are sparse under software GL.
- **Local Linux host (Ubuntu 26.04, WSL):** `PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=ubuntu24.04-x64`; WebKit needs its
  listed system packages, ICU 74 / libvpx 9 / libxml2 `.so.2` from Ubuntu 24.04 unpacked into
  `~/.local/lib/webkit-noble` and linked into the bundle's `minibrowser-wpe/sys/lib`, `LIBGL_ALWAYS_SOFTWARE=1` (the
  configs set it for WebKit) and a GStreamer audio sink (`gstreamer1.0-plugins-good`, `gstreamer1.0-pulseaudio`).

## Findings left open

**F1 — slow engines stall playback at a page turn right after a seek.** Page renders share the engine queue. After a
seek the audio buffer is nearly empty; if the next page is due immediately and was not prefetched (the Phase 6
prefetch waits for a cushion of max(1.5 s, 3 average renders)), its render blocks audio pulls for longer than the
buffer lasts. With Playwright Firefox's 1.2–2.6 s renders the clock froze ~1.7 s, and a page-1 measure highlight was
observed over page 3 during the stall (root cause not established). Slow phones can hit the same case. Proposed fix
(needs a decision; changes the Phase 6 policy): when a turn is due but buffered audio is shorter than the expected
render, keep the current page ("Preparing page N…") until the cushion allows, so audio always wins.

**F2 — cold first Play waits for the soundfont.** Static build, first context: 7.1 s, of which 6.1 s waiting for the
background soundfont warm-up (native preparation 0.4 s, first pull 9 ms). Later contexts 543–564 ms; warm starts
117–134 ms. Phase 8 saw the same first-context outlier. The test serves the 13 MB font from disk through a Playwright
route; a real first visit needs a device measurement.

**Wording:** with `VideoEncoder` present but no encodable codec, the export says "WebCodecs is not available"; it
should say no supported video encoder.

## Release escape hatches

Build-time, documented in `docs/BUILD_EMBED.md`, implemented in `lib/playback/release-gates.ts`:

- `NEXT_PUBLIC_OTS_PLAYBACK_CURSOR=segment` (no follow map; the cursor steps by note) or `measure` (measure tracking
  only; the player's note highlighting and the export's moving cursor are hidden). Default `continuous`.
- `NEXT_PUBLIC_OTS_PLAYBACK_AUTOFOLLOW=0`: no automatic page turns or scrolling and no Follow toggle; Jump to playback
  still works.

Audio, speed and repeat controls are never gated. `tests/playback-release-gates.spec.ts` passes (2/2) against a gated
server: the editor tracks measures, calls neither `segmentPositions` nor `playbackFollowMap` and does not turn pages;
the player has no note mode, moving cursor or export cursor option. It skips on an ungated build. Unit tests cover
the parsing and that following cannot be re-enabled.
